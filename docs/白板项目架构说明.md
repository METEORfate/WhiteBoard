# 协作白板架构说明

项目根目录 `whiteboard/`，Node.js ≥ 20，零运行时依赖。

## 一、分层

系统分五层，自下而上。

**持久化层** `server/store.js`
按房间维护一个 JSONL 文件，追加写、顺序重放、按行数阈值压缩成快照。对外暴露 `load / append / compact / has / lineCount`。

**传输层** `server/ws.js`
RFC 6455 实现，负责握手、分帧、掩码、分片、控制帧、关闭码。对外暴露 `WSConnection`、`acceptUpgrade`，另附测试用客户端 `connectWS`。

**应用消息层** `shared/protocol.js` + `server/index.js` + `client/js/net.js`
定义九种消息类型及其字段，负责会话建立、消息分发、限流、校验与归一化。服务端入口在 `index.js`，客户端状态机在 `net.js`。

**文档同步层** `shared/merge.js` + `server/room.js` + `client/js/store.js`
定义 op 语义与字段级合并规则。服务端 `Room` 持有权威状态与三张去重账本，客户端 `DocStore` 持有本地副本、待发队列与撤销栈。

**呈现层** `client/js/canvas.js` `tools.js` `presence.js` `ui.js` `welcome.js`
画布渲染、视口变换、命中测试、指针事件与工具状态机、远端光标、DOM 面板。

另有一层横切：`shared/` 下三个文件同时被浏览器和 Node 以同一份 ESM 加载，是两端共用的规则来源，不单独成层。

## 二、概念

**Op（操作）**
一次编辑意图的传输单位。字段：`opId`、`roomId`、`clientId`、`sessionEpoch`、`clientSeq`、`kind`、`target`、`shapeType`、`ver`、`patch`、`ts`。`kind` 取 `create` / `patch` / `delete`。

**Cell（字段单元）**
单个可同步字段的值及其戳，形如 `{ val, v, c, o }`。是合并的最小单位。

**Shape（带戳图形）**
`{ id, type, fields: { 字段名: Cell } }`。每个字段各自持有独立的戳，同一 op 写入的字段共享同一个戳。

**Flat（扁平视图）**
`flatten(shape)` 的返回值，去掉戳、补默认值后的纯值对象。渲染、命中测试、导出只消费这一形态。

**Stamp（戳）**
三元组 `(v, c, o)`，即版本号、写入者 clientId、写入它的 opId。按字典序比较，构成全序，任意两个戳不并列。

**Tombstone（墓碑）**
`deleted` 字段被写成 `true` 的图形。删除不物理移除记录，图形保留在 `shapes` 表中但不可见。

**Room（房间）**
一个独立文档副本及其成员。持有 `shapes`、`hwm`、`seen`、`pruned`、`members`、`presence`、`pendingPresence` 七个结构。

**Connection（连接）**
一条 WebSocket 物理连接，标识 `conn-<n>`。同一 clientId 可对应多条连接。

**Member / Presence（成员）**
`{ clientId, name, color, cursor }`。不进入文档状态，不落盘。

**seen**
`opId → 内容指纹`，用于幂等去重与「同 opId 异内容」检测。上限 50000，按插入顺序淘汰。

**hwm（高水位）**
`clientId:sessionEpoch → 已处理的最大 clientSeq`，用于拒绝序号倒退。上限 500，按 LRU 淘汰。

**pruned**
已被配额回收的墓碑 id 集合，用于阻止旧 create 重放使图形复活。上限 2000。

**pending（待发队列）**
客户端未确认的 op 列表，按 `clientSeq` 升序，持久化在 localStorage。

**inflight（在途窗口）**
已发出但未收到 ack 的 op 集合，上限 32 条，单条超时 5 秒。

**rebase（重基）**
将一条被判定为版本落后的 op 换新 opId、以 `max(本地版本, 权威版本) + 1` 重发的操作，只执行一次。

**六个标识符**

| 名称 | 生成方 | 作用域 | 存储 |
| --- | --- | --- | --- |
| `opId` | 客户端，uuid v4 | 全局 | op 内、seen 表 |
| `shapeId` | 客户端，uuid v4 | 房间内 | shape.id |
| `clientId` | 客户端，`c-` + 10 hex | 标签页 | sessionStorage |
| `sessionEpoch` | 客户端，时间戳 + 随机 | 一次页面加载 | localStorage |
| `bootEpoch` | 服务端，进程启动时 | 一次进程生命周期 | 内存 |
| `roomId` | 用户输入或随机 8 位 | 全局 | URL `?room=` |

`roomId` 进入系统时归一化为 `trim().toLowerCase()`，因为它同时用作内存 Map 的键和磁盘文件名。

**三个序号**

`clientSeq` 由客户端分配，在 `(clientId, sessionEpoch)` 内单调递增。
`serverSeq` 由服务端分配，在房间内单调递增，是广播帧的顺序依据。
`ver` 由客户端分配，在单个图形内单调递增，等于该图形所有 Cell 版本的最大值加一。

## 三、数据结构

### 可同步字段

`FIELD_SPEC` 定义 12 个字段，白名单之外一律拒绝。

| 字段 | 类型 | 范围 | 默认值 |
| --- | --- | --- | --- |
| `x` `y` | 整数 | -100000..100000 | 0 |
| `w` `h` | 整数 | 2..20000 | 160 / 120 |
| `fill` `stroke` | 颜色 | `#rrggbb` / `#rrggbbaa` / `transparent` | `#ffffff` / `#1f2933` |
| `strokeWidth` | 整数 | 0..64 | 2 |
| `text` | 字符串 | 最多 2000 码点 | `''` |
| `fontSize` | 整数 | 6..400 | 20 |
| `pts` | 整数数组 | 最多 2000 点，偶数长度 | `[]` |
| `z` | 整数 | 0..1e15 | 0 |
| `deleted` | 布尔 | — | false |

`pts` 是画笔采样点，存相对图形左上角的坐标，扁平排列 `[x0,y0,x1,y1,…]`。
`z` 在创建时取 `Date.now()`；相等时按 id 字典序决定绘制顺序。

图形类型 `SHAPE_TYPES` 取 `rect` / `ellipse` / `text` / `pen`，创建后不可变更。

### 限制常量

`LIMITS` 定义 17 项上限，主要有：单帧 64 KiB、坐标 ±100000、单图形边长 20000、单笔 2000 点、单 op 12 个字段、单房间 5000 个图形、服务端 60 条/秒突发 120、协议违规累计 20 次断开。

### op 结构

```json
{
  "opId": "uuid", "roomId": "demo", "clientId": "c-xxx",
  "sessionEpoch": "...", "clientSeq": 17,
  "kind": "patch", "target": "<shapeId>", "shapeType": "rect",
  "ver": 6, "patch": { "x": 120, "y": 80 }, "ts": 1793021300922
}
```

约束：`create` 必带 `shapeType` 且 patch 含 `x/y/w/h`，`pen` 另需 `pts` 至少 4 个数值；`create` 强制 `deleted=false`，`delete` 强制 `deleted=true`；patch 非空且不超过 12 个字段；`ver` 为 1..1e9 且不超过 `maxVersion + 1`。

### 磁盘记录

```jsonl
{"seq":1,"shape":{...}}
{"snapshot":true,"seq":37,"shapes":[{...}]}
```

增量记录存变更后的完整图形。快照记录重放时先清空再装载。日志行数达 500 时压缩。

## 四、协议

### 传输层

RFC 6455，仅文本帧。

握手：校验 `Upgrade: websocket`、`Sec-WebSocket-Key`（base64 解码后 16 字节）、`Sec-WebSocket-Version: 13`，响应 `Sec-WebSocket-Accept = base64(sha1(key + "258EAFA5-E914-47DA-95CA-C5AB0DC85B11"))`。

分帧：解析 FIN / RSV / opcode / MASK / 7·16·64 位长度；客户端帧必须带掩码，服务端帧不带；支持 continuation 帧重组，累计长度受 64 KiB 限制；控制帧不可分片且载荷不超过 125 字节。

关闭码：1000 正常、1001 关闭或空闲超时、1002 协议错误、1003 收到二进制帧、1007 非法 UTF-8、1008 策略违规、1009 超长、1006 异常断开；应用层另有 4000 心跳超时、4001 模拟断网、4002 触发重同步。

### 应用消息

| 类型 | 方向 | 字段 |
| --- | --- | --- |
| `hello` | C→S | roomId, clientId, sessionEpoch, name, lastSeq |
| `welcome` | S→C | roomId, bootEpoch, serverSeq, shapes[], members[] |
| `op` | C→S | op |
| `ack` | S→C | opId, accepted, duplicate, seq, shape |
| `presence` | 双向 | event(join/leave/move), clientId, name, color, cursor |
| `resync` | S→C | reason |
| `error` | S→C | code, message, opId |
| `ping` | C→S | t |
| `pong` | S→C | t, serverSeq |

约束：`hello` 须在连接建立后 10 秒内到达；`op` 广播包含发起者；`ack` 仅用于将 op 移出待发队列，不推进 `lastAppliedSeq`。

### 会话时序

```
C → S  hello
S → C  welcome（先发快照，再标记 joined，期间广播进缓冲）
C → S  op
S → C  op（广播，含发起者）
S → C  ack
C ⇄ S  presence / ping / pong
```

### 校验规则

`normalizeField` 对数值型字段执行取整与越界钳制，对 `NaN`、`Infinity`、非数字、非法颜色、超长文本返回拒绝。文本长度按码点计数。

`normalizeOp` 校验 opId、roomId、clientId、sessionEpoch 格式，clientSeq 为 1..1e12 整数，ver 为 1..1e9 整数，kind 合法，patch 非空且字段数不超限，create 的几何字段齐全。

`normalizeShape` 校验 id、type、每个 Cell 的 `v`（1..1e9 整数）、`c`（合法 clientId）、`o`（uuid），并对 `val` 重新归一化。

### 错误码

| 码 | 触发 | 客户端处理 |
| --- | --- | --- |
| `BAD_JSON` `BAD_MESSAGE` `UNKNOWN_TYPE` | 消息层非法 | 计数，累计 20 次断开 |
| `RATE_LIMITED` | 超出令牌桶 | 清空在途标记，500ms 后重发 |
| `BAD_*` `MISSING_*` | 字段或结构非法 | 从队列移除 |
| `ROOM_MISMATCH` `CLIENT_MISMATCH` | 身份与连接不符 | 从队列移除 |
| `OPID_CONFLICT` | 同 opId 不同内容 | 移除并重同步 |
| `SEQ_RESET` | clientSeq 不大于高水位 | 移除并重同步 |
| `UNKNOWN_SHAPE` | 目标图形不存在 | 移除并重同步 |
| `SHAPE_PRUNED` | 墓碑已被回收 | 移除并重同步 |
| `TYPE_CONFLICT` | 同 id 改类型 | 移除 |
| `VER_TOO_FAR` | ver 超过 maxVersion+1 | 移除并重同步 |
| `ROOM_FULL` | 图形数达上限 | 移除 |
| `ROOM_LIMIT` `ROOM_RATE_LIMITED` | 建房配额不足 | 提示，不进房 |

`ack{accepted:false}` 不是错误，表示合并后无状态变更，客户端采用返回的权威图形并重基一次。

### HTTP 接口

| 路径 | 说明 |
| --- | --- |
| `GET /` | 白板或落地页，由前端按有无 `?room=` 分流 |
| `GET /client/*` `GET /shared/*` | 静态资源，仅挂载这两个目录，路径穿越返回 403，带弱 ETag 与 304 |
| `GET /healthz` | `{ok, bootEpoch, rooms}` |
| `GET /api/stats` | 房间清单，生产环境或非回环地址返回 403 |
| `GET /api/rooms/:id` | `{exists, members, shapes}`，不返回内容，每 IP 30 次/分 |

## 五、操作

### 文档操作

`create`：新建图形。patch 携带几何与样式，`z` 取创建时间戳，版本为 1。
`patch`：修改若干字段。版本为图形当前最大版本加一，未涉及的字段保持原值。
`delete`：写 `deleted=true`，版本加一。记录保留。

### 本地操作

创建、移动、缩放、改样式、改文本、删除、复制、粘贴、再制、置顶置底、撤销、重做、导出 PNG、平移、缩放视图、框选、全选。

移动与缩放期间只更新预览，每 60ms 提交一次 op，松手补最终提交；整段拖动合并为一条撤销记录。
样式调整以事务形式记录：`beginStyleEdit` 拍快照，`endStyleEdit` 合并，800ms 空闲兜底。
撤销与重做不重放旧 op，而是以当前版本加一构造新 op。
粘贴复制扁平视图快照并生成新 id 与新版本，连续粘贴每次偏移 20px。

### server/store.js

`load(roomId)` 顺序重放日志并返回 `{shapes, seq, lines, truncated}`，坏行跳过，`seq` 取出现过的最大值，存在坏行时立即压缩；`append(roomId, record)` 同步追加；`compact(roomId, shapes, seq)` 写临时文件后 rename；`has(roomId)` 仅 stat 不加载。

### server/index.js

`getRoom` 懒创建并加载房间；`hasRoom` 判断内存或磁盘是否存在；`checkCreateQuota` 检查全局房间数与每 IP 滑动窗口；`takeToken` 连接级令牌桶；`takeProbeToken` 探测接口每 IP 令牌桶；`handleHello` 校验身份并进房；`handleOp` 调用 `Room.applyOp` 并回 ack 或 error；`reapRooms` 卸载空闲房间并清理配额记账；`start` / `stop` 启停，端口冲突时默认顺延 10 个。

### client/js/tools.js（Interactions）

`setTool(name)` 切换工具并清理预览与选择；`_onPointerDown/Move/Up` 按工具进入 pan / marquee / create / draw / move / resize 分支，仅接受首个 pointerId；`_throttleCommit()` 每 60ms 提交预览；`_commitPatches()` 写入 store；`_startMove` `_startResize` 记录起点快照；`recordUndo` 合并撤销；`_openTextEditor` `_commitText` 内联编辑，提交时重算包围盒；`_penDraft(points)` 由世界坐标点生成相对坐标的画笔草稿，采样间隔 2px、上限 2000 点；`copySelection` `paste` 基于扁平视图快照。

模块级函数 `normalizeRect`、`resizeRect`、`measureTextBox`。

### 其他

`presence.js` 的 `Presence`：`setMembers` 初始化、`handle(msg)` 处理加入/离开/移动、`render()` 按视口重排、`sendLocal(pt)` 80ms 节流上报。

`rooms.js`：`randomRoomId` 从 32 字符表生成 8 位房间号，`slugRoomName` 整理中文与空格，`parseRoomInput` 兼容链接与裸房间号，`probeRoom` 探测存在性，`rememberRoom` 维护最近记录。

`ui.js` 的 `UI`：状态条、成员列表、属性面板、缩放控件、调试面板、toast。

`main.js`：`pickRoom` 从 URL 取房间号，`loadIdentity` 装配 clientId 与 sessionEpoch，`bootBoard` 按 store → board → interactions → net → presence → ui 的顺序装配。

## 七、不变量

1. `shared/` 是客户端与服务端唯一的规则来源。
2. 合并按字段进行，取戳较大者，不做整图形覆盖。
3. 戳按 v → c → o 比较，任意两个戳不并列。
4. `lastAppliedSeq` 只由快照与广播推进，不由 ack 推进。
5. `serverSeq` 出现缺口时全量重同步，不做增量续接。
6. 服务端先落盘再广播。
7. 删除只打墓碑，不物理移除。
8. `op.ver` 在入队时确定，重试不重算。
9. 撤销与重做生成新 op，不重放旧 op。
10. 房间号先校验后归一化，不以归一化后的空串建房。
11. 握手首帧在监听器注册完成后才投递。
12. 限流必须回错误，不静默丢弃。
13. 数组类型默认值不共享引用。

## 八、边界

单进程内存态，仅支持单实例部署。
无鉴权，房间号即凭证。
同一字段并发写入为后写者胜，不做意图叠加；文本为整串替换。
房间无归属与过期删除，空闲房间仅从内存卸载，磁盘文件保留。
