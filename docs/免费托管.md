# Render 免费托管

本项目使用常驻 Node.js 进程提供 HTTP 和 WebSocket，不能直接作为静态网站部署。仓库根目录的 `render.yaml` 声明 Render 免费 Web Service，复用现有服务，不增加运行依赖或构建工具。

## 配置

| 项目       | 配置                                            |
| ---------- | ----------------------------------------------- |
| 源码       | `METEORfate/WhiteBoard` 的 `master` 分支        |
| 运行环境   | Node.js 22                                      |
| 部署前校验 | `node --test "tests/*.test.js"`                 |
| 启动       | `node server/index.js`                          |
| 健康检查   | `/healthz`                                      |
| 监听       | `0.0.0.0`，端口由 Render 的 `PORT` 环境变量提供 |
| 实例       | 单个 Free 实例，新加坡区域                      |
| 自动更新   | 推送到 `master` 后自动部署                      |
| 自定义域名 | `whiteboard.dree.shop`                          |

`STRICT_PORT=1` 保证端口冲突时直接退出，避免自动顺延导致平台无法连接。浏览器现有网络层会根据 HTTPS 自动使用 WSS，无需单独配置 WebSocket 地址。

## 首次部署

1. 登录 Render，在 New → Blueprint 中选择此仓库和 `master` 分支，读取根目录 `render.yaml`。
2. 核对只有一个 **Free Web Service**，不创建付费磁盘或数据库，然后部署。
3. 等服务变为 Live 后，记录 Render 实际分配的 `*.onrender.com` 主机名，不能根据服务名称猜测。
4. 在该服务 Settings → Custom Domains 中确认已添加 `whiteboard.dree.shop`。
5. 在 Cloudflare 的 `dree.shop` DNS 中新增记录：类型 `CNAME`，名称 `whiteboard`，目标为上一步实际分配的 Render 主机名，代理状态为 **DNS only**。
6. 返回 Render 验证域名，等待 HTTPS 证书生效。

只修改 `whiteboard.dree.shop` 的记录，现有主站不需要迁移。

## 免费实例的数据与唤醒行为

- 连续 15 分钟没有 HTTP 请求或 WebSocket 消息时可能休眠；再次访问通常需要约一分钟唤醒。
- **休眠、重启、重新部署均会清空服务端磁盘上的房间数据**。`data/` 未提交 Git，部署也不会上传本机已有白板。
- 浏览器本地缓存与未确认队列仍保存在原浏览器中，但不能把它们当作服务端备份；新设备和重连后的房间内容以服务端同步结果为准。
- 重要白板请使用现有 PNG 导出功能留存，PNG 只保存图像，不是可编辑备份。
- Render 的免费额度由工作区共享。保持 Free 实例，不开启付费资源；流量和构建额度的超额策略需在账户中检查，不能仅凭 `plan: free` 保证账户所有资源零收费。

## 上线验收

部署配置已准备不代表已上线；必须以实际检查结果为准：

1. `https://whiteboard.dree.shop/healthz` 返回 HTTP 200，JSON 中 `ok` 为 `true`。
2. 首页、`/client/js/main.js` 和 `/shared/protocol.js` 能以 HTTPS 加载。
3. 两个浏览器窗口加入同一房间，在一端画图后另一端立即出现；模拟断网编辑，恢复后两端收敛。
4. `/api/stats` 从公网返回 403；确认房间列表没有暴露。
5. 记录部署提交、Render 服务地址、域名验证和以上检查结果。
